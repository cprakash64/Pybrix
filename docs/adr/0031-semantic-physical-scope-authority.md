# Semantic physical-scope authority

A native split proves a geometrically valid partition. An uncertified fused semantic proposal also needs explicit intent over that physical result before READY and Apply.

## Policy and authority boundary

Only the existing positive `StructuralOwnershipCardinality.IDENTIFIED` proof can exempt a fused semantic PLANE from confirmation. The semantic engine projects that existing proof and its exact source-space plane into suggestion metadata. No certificate creation, ordering, publication predicate, threshold, geometry algorithm or candidate cap changes. The worker registers this projection from its own decomposition, never from client payload. A native fallback at a different exact plane loses the exemption. Confidence, peer grounding, BOTH and TWO_WAY_UNRESOLVED do not substitute for IDENTIFIED.

All other fused semantic planes require explicit physical-scope confirmation. Direct COMPONENT/family operations and manual split retain their existing contracts. An unavailable candidate is not exposed by this mechanism; W-14 remains separate work.

## Native Preview receipt

After a successful current native Preview and winner registration, the trusted worker issues an opaque UUID plus worker-local sequence identifier. One current receipt is kept. Its record binds:

- source document, revision and part in the native ticket;
- preparation and semantic candidate/alternative in the worker proof;
- source mesh identity and semantic candidate-set generation through the registered worker object identity and live mesh reference;
- exact binary-rational hyperplane and oriented positive physical side;
- exact native ticket/generation and immutable stored result document, containing piece A, piece B and boundary;
- current-source, confirmation, cancellation, expiry and consumption state.

The physical identity is the immutable worker-owned result object, not a client-supplied hash and not another result at a numerically similar plane. No mesh copies are stored in the authority record. Legacy plane-setting tolerance only selects among existing registered planes; receipt authority uses the actual registered winner and exact physical identity.

The receipt is attached to the same native ticket with a trusted commit-policy closure. Therefore removing semantic metadata from a commit request, forging READY, or clearing/replacing a semantic registry cannot downgrade this ticket into a manual transaction. The semantic registry object itself is the candidate-set generation: replacement invalidates old records without changing geometry.

## Confirm and READY

`split/confirm-scope` accepts only `{ receiptId }`. The worker rejects extra geometry/identity fields, missing, malformed, guessed, consumed, cancelled and stale receipts. It verifies that the exact stored physical result is still live, marks the worker record confirmed, and returns only the existing ticket and updated semantic proof. It performs no native work, builds no second geometry result, and transfers no duplicate render arrays. The main thread keeps its inspected render.

The existing Option A/B path uses the same operation. A `boundaryChoice: CONFIRM` on a new split/create request is refused; it is not a substitute for a receipt. Both ordinary and boundary controls appear only with a completed physical Preview. Piece A is the selected semantic piece, Piece B remains separate, and None/Cancel declines without authority. Automated checks do not establish human comprehension.

`AutoSplitSession.nativeQualified` requires a worker receipt for semantic fused READY. REQUIRED withholds READY; CONFIRMED admits the selected candidate; AUTOMATIC_IDENTIFIED additionally requires the matching trusted IDENTIFIED projection and exact oriented plane. Shared complementary rows do not inherit another candidate's confirmation.

## Commit, lifetime and races

`SplitCandidateStore` owns the trusted commit-policy closure on the exact entry. Semantic authorization is rechecked before payload validation or mutation. A valid confirmed/automatic authorization is consumed before an authorized commit attempt, including a later failing commit; retries need a fresh Preview lifecycle. Requests with no confirmation have no authorization to consume. Ordinary manual transactions have no semantic guard and retain their existing safe transaction behavior.

Source/revision/mesh/part mismatch, new preparation, new candidate set, stale ticket, cancellation/discard, document release, successful Apply and expiry invalidate authority. Native ticket generation and resident-source checks remain independent. Lookup is cleared on registry replacement, document release, cancel, consumption and four-minute expiry. An expired record cannot be reconfirmed. Cancelled/consumed entries remain denied by their ticket closure until the candidate store releases that ticket. There is one lookup record and constant scalar bookkeeping per existing live ticket; no unbounded token registry or duplicated mesh storage.

Confirm and commit authorization are synchronous worker transitions before their result messages. Current registry/source/ticket checks close races with supersession or source mutation. UI cancellation discards the same native ticket and ignores late completion. Once commit authorization is consumed, no second commit and no Undo can restore it. Source part changes in the workspace use the existing release/discard lifecycle; another part cannot use this ticket because commit independently checks the ticket part.

This contract is a local safety hardening. It provides no new semantic-quality, human-comprehension, release-performance or qualification claim.
